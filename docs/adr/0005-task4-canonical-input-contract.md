# ADR-0005: 任务4以唯一规范提交信封隔离上游来源格式

## Status

Accepted - 2026-08-01

任务四需要同时接收原始附件、任务一至三及外部系统的异构结果，并在重试、晚到、修正和部分失败下保持 #3 的不可变证据图、#5 的信任边界与 #6 的原子接纳和生命周期语义。任务四因此只信任一个与传输方式无关的**规范提交信封**：来源格式必须先由登记的**来源适配器**确定性转换，再经过统一的身份、版本、完整性、因果、内容安全和证据资格门槛；适配器不能授权、规范化、选择证据、消解冲突、改写生命周期、选择规则或按输入指令访问网络和文件。

规范提交按认证租户、来源系统和上游业务申请引用确定身份，以范围化幂等键和服务端语义指纹去重；附件只能引用受控上传或不可变受控对象，并独立验证媒体类型、字节数和 SHA-256。单据与页归属由上游作为候选声明提交，字段只能作为带完整生产者、运行、输入、时间、置信语义和页/坐标溯源的观察提交；原始值、任务四的规范化结果和字段事实保持分离。全量、增量、替代、撤回、批次结束和乱序均只追加表达，每封信封原子接纳，并以独立的结构版本、语义版本、稳定回执和原因码管理兼容及恢复。

当前真实材料仅证明单页 JPEG/PNG 机动车登记证及材料目录中两种未版本化 OCR 形态；其他单据和跨单据输入只能以明确标记的受控场景验证，不能声称具有真实样本覆盖。具体字段 schema、处置矩阵、原因码、适配约束和 conformance fixture 分层由[定义规范输入、字段证据与上游适配契约](https://github.com/Lijika/xiaopeng_comp/issues/7)的 canonical resolution 持有；规则发布治理、数据库、消息队列、云产品和传输产品由后续决策选择。

## Considered Options

- 让每种来源格式直接进入生命周期或校验：接入较快，但会把来源歧义、网络权限和可覆写值泄漏进核心边界。
- 让适配器输出“当前字段事实”：模型简单，但无法诚实保留多候选、缺失语义、生产者溯源和后续失效关系。
- 以唯一规范提交信封统一接纳、把适配器限制为不可信的确定性翻译器：适配和 conformance 成本更高，但能集中执行安全、幂等、版本、证据与生命周期不变量。

## Consequences

- 所有来源，包括现有 MVP 和材料目录中的 OCR 产物，都必须通过同一规范门槛；“能被旧代码解析”不构成受支持或可信。
- 未知生产者、模型、置信语义或坐标事实必须显式保留为未知；记录留存不自动取得证据资格，也不得补造溯源。
- 契约 fixture 证明结构、语义、适配和安全行为，不证明 OCR 准确率或真实跨单据性能。
