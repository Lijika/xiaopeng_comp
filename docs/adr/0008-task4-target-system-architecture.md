# ADR-0008: 任务四采用模块化单体控制面与隔离运行平面

## Status

Accepted - 2026-08-01

Canonical resolution: [确定目标系统架构、持久化与运行边界](https://github.com/Lijika/xiaopeng_comp/issues/11).

## Context

任务四已经确认不可变证据图、申请生命周期唯一状态所有者、规范提交信封、不可变治理策略发布、公开演示与受控部署隔离，以及证据分离的双轨评估协议。目标架构必须把这些语义落到可持久、可并发、可恢复和可审计的模块接口上。

当前 MVP 的运行路径是扁平 `Application` JSON 在一次进程内调用中经 `RuleEngine` 生成 `Report`。FastAPI、CLI 和评估器直接读取 YAML、JSON、fixture 和本地路径；规则与知识通过文件覆写，审计尽力追加到 JSONL，校验没有申请生命周期、运行身份或持久状态。它证明了标准化、匹配、规则和报告行为，但不能承担受控部署中的状态、证据、治理、并发或信任权威。

本决议选择目标模块、权威所有者、持久化模型、同步与异步接口、并发和恢复语义、部署拓扑、技术基线与可观测性。它不裁决现有 MVP 各文件的保留、重写或退役，也不实施代码。

## Decision

### 1. 总体形态

目标系统采用**模块化单体控制面 + 独立异步 worker + 隔离评估运行平面**，不默认拆成微服务。

```text
来源适配器 / 受控上传
          |
          v
       接入模块 ---- 原子接纳 ----> 证据模块
          |                            | 固定快照
          +------------------------> 生命周期模块
                                           | 持久任务
                                           v
                                      校验 worker
                                           | 完整运行
                                           v
                                  生命周期修订仲裁与路由
                                           |
                                  人工决定 / 下游交付

策略工件注册表 + 策略治理账本 -- 发布引用/影响事实 --> 生命周期模块
隔离评估 runner -- 只读快照与发布 --> 不可变评估运行包
```

所有目标模块位于同一代码库和控制面部署单元内，通过明确接口协作。HTTP、CLI、worker、数据库、对象存储、身份源和消息传输都是模块接口处的适配器。模块不得跨过接口直接写其他模块的表，也不得把数据库表、文件路径、队列消息或全局单例暴露为业务接口。

首版使用一个物理 PostgreSQL 集群和逻辑分域 schema/table，以短事务保持跨域接纳、运行提交和必要审计的原子性。只有当独立伸缩、团队所有权或故障隔离已有运行证据时，才重新评估物理拆分。

### 2. 权威所有者与模块接口

| 模块 | 权威拥有的事实 | 主要接口结果 |
| --- | --- | --- |
| 接入模块 | 接入尝试、提交流/批次因果、命令幂等绑定、提交回执、接入隔离 | 稳定回执、接纳或隔离处分、原因码 |
| 证据模块 | 附件/页引用、单据实例及归属、字段观察、人工修正、规范实体、实体链接、证据修订、证据快照清单 | 新证据修订或不可变快照引用 |
| 生命周期模块 | 申请处理周期、生命周期事件、主阶段、工作项及 claim、当前校验运行引用、核验路由、取消、重开、下游交付义务 | 接受事件、当前修订或稳定拒绝原因 |
| 校验运行模块 | 运行规格、执行尝试、规范化结果、字段证据选择、校验发现、完成/失败/失效事实 | 不可变运行结果引用 |
| 人工决定账本 | 人工处置与例外决定及其固定上下文 | 不可变决定引用 |
| 策略工件注册表 | 不可变策略组成工件、版本、摘要及兼容关系 | 工件或治理策略发布引用 |
| 策略治理账本 | 候选冻结、验证、审批、调度、激活、安全冻结、回滚和影响事实 | 治理事件和精确生效发布引用 |
| 安全审计账本 | 需问责业务与安全动作的只追加事实及完整性信息 | 审计事件引用和授权查询结果 |
| 评估计划/标签域 | 冻结 cohort、split、应评机会、金标、扰动、种子和预算 | 冻结计划引用 |
| 评估运行包仓库 | 正式评估全部输入、输出、环境、指标、区间和状态 | 内容寻址的运行包引用 |

模块接口采用命令与不可变引用，而不是通用 CRUD：

- 接入接口接收规范提交信封、主体与幂等上下文，隐藏认证、契约、因果、隔离和原子接纳细节。
- 证据接口接收带预期 `evidence_revision` 的追加命令，并可按固定请求生成不可变证据快照。
- 生命周期接口接收带预期 `lifecycle_revision` 的类型化命令，返回被接受事件或稳定拒绝原因。
- 校验接口只接受完整 `RunSpec` 并返回 `RunResult`；它不能读取“当前”文件、规则、知识或申请状态。
- 策略运行时接口只按租户、环境和可信时间解析精确 `policy_release_id`。
- 评估接口只接受冻结计划引用并返回 job 或运行包引用，不能调用产生业务副作用的生命周期命令。
- 查询接口只返回按角色最小化的 DTO、权威修订和投影水位。

### 3. 接入与申请接纳

来源适配器只把已登记来源格式确定性转换为规范提交信封，不拥有认证、幂等、证据选择、规范化或状态。受控上传模块只拥有上传授权和封存对象引用，上传完成不自动产生申请或证据。

首次合格提交通过申请接纳接口，在一个数据库事务内共同建立：

- 工作台申请标识和上游业务申请引用绑定；
- 接入幂等绑定和稳定提交回执；
- 首个生命周期事件；
- 初始证据事实和证据修订；
- 必要安全审计；
- 后续处理所需 outbox/job。

后续提交同样原子提交回执、证据修订、必要生命周期事实、审计和 outbox。事务失败不得留下半接纳申请或半推进证据。隔离内容不是证据图；修复通过新的恢复事实和接纳尝试表达，不能原地改写旧尝试。

昂贵内容检查可以异步执行，但只有已封存、已登记且满足适用接纳门槛的对象才可进入证据图。

### 4. 证据、校验运行与生命周期

证据模块拥有原始事实、规范实体、实体链接、单调证据修订和不可变快照。标准化结果属于固定校验运行，不回写字段观察；校验运行拥有其规范化、字段证据选择和校验发现。

生命周期模块是申请状态的唯一所有者。校验完成时，它以预期的处理周期、`lifecycle_revision`、`evidence_revision`、`policy_release_id` 和校验器版本执行 compare-and-set：

- 全部固定输入仍匹配时，完整运行可成为当前校验运行并进入路由判定；
- 任一输入已变化时，运行永久保留并标记失效，但不得成为当前依据；
- 部分发现、暂存文件或未可靠完成的运行不可见、不可路由。

人工修正只向证据模块追加观察、归属或实体链接事实。证据修订推进后，生命周期失效旧运行及其依赖工作项，并重新经过组装、证据就绪、校验和路由。

### 5. 人工复核与例外

生命周期模块拥有复核、修正、补件和例外工作项的创建、claim lease、失效和收束。人工决定账本拥有不可变的人工处置和例外决定；每项决定固定处理周期、运行、发现、证据快照、策略发布、主体角色、结构化理由和必要的受限备注。

人工处置不能覆盖自动校验结论。例外批准只能在固定有效范围内参与核验路由，不能把“不一致”改写为“一致”。人工修正通过证据模块追加事实，补件通过接入模块形成新附件版本。

提交人工决定时同时校验生命周期、工作项、证据修订、claim fencing token、命令幂等和职责分离。决定事实、生命周期事件和必要审计必须在同一事务中生效；任一条件失败则全部不生效。

### 6. 策略工件、治理与运行时选择

可编辑草案是非权威工作区。提交后冻结的策略工件按内容摘要进入策略工件注册表；策略治理账本只追加验证、审批、调度、激活、冻结和回滚事件。`active release` 是账本派生投影，不是可直接覆写的配置。

每个校验运行由服务端按租户、环境和可信时间选择一个完整治理策略发布，并固定 manifest 与全部摘要。调用方不能传入任意规则路径、知识路径、`latest` 或组成工件的独立版本。

策略影响分析生成无漏项的保守影响集并向生命周期发布影响事实。策略模块不能直接改申请状态；只有生命周期可以据此失效当前运行、建立业务重新校验或开启显式追溯周期。

公开演示可以导入导出 YAML/JSON 作为会话材料。受控部署禁止直接热改运行文件、请求选版或绕过候选验证与审批激活。

### 7. 正式评估运行平面

评估计划与金标独立于预测结果。评估 runner 使用独立身份、队列、暂存区和写入凭据，只读冻结计划、证据快照、治理策略发布、校验器制品和标签。它可以复用同一纯校验内核，但不能创建或修改业务申请、生命周期、当前校验运行、路由、工作项或策略激活。

执行中的 evaluation job 可以记录 lease、尝试和恢复状态。结束时无论状态为 `INVALID`、`INSUFFICIENT`、`FAIL`、`PASS(scope=...)` 或 `SMOKE_ONLY`，都封存为内容寻址的不可变评估运行包。重跑创建新包并引用前包，不能覆盖历史。

PostgreSQL 保存运行登记、状态与 manifest 哈希；完整运行包保存于对象存储。真实样本轨运行包留在受控环境，公开发布只包含不可反推的代号、哈希、聚合统计、公式、区间和复现框架。

### 8. 持久化模型

受控部署使用 PostgreSQL 作为结构化权威事实源，S3 兼容对象存储保存原始附件、派生产物和大型不可变制品。数据库只保存不透明对象引用、内容摘要、分类、保留、法律保全和删除凭证。

生命周期、证据、运行、人工决定、策略治理、审计、幂等、inbox/outbox 和持久任务按逻辑域分表。当前态、队列视图、搜索索引、报告和统计都是可重建投影或缓存，不能反向成为权威。

安全审计在逻辑上独立于普通业务修改权限。受保护动作所需审计事实与业务事实共同提交，再异步完整复制到机构 WORM/SIEM。外部审计副本不成为申请状态所有者。

公开演示可以使用 SQLite 或本地临时目录，但只能处理合成或经验证不可逆匿名化数据，并且不构成受控部署持久化实现。

### 9. 同步与异步接口

系统采用“同步提交权威命令，异步执行耗时工作”：

- 同步接口完成身份、权限、契约、幂等和预期修订校验，并在一个短事务内写权威事实、必要审计和 outbox；返回稳定回执、修订或冲突。
- 申请接纳、人工处置/修正、工作项认领、例外决定、取消/重开及策略治理命令使用同步提交。
- 内容检查、证据组装与就绪、校验运行、策略验证/影响分析/重跑、正式评估、受控导出和下游交付由异步 worker 执行。
- worker 只能提交领域命令或结果事实，不能直接改生命周期投影。
- 查询通常读取投影，并返回投影水位和权威修订。命令成功不表示所有查询视图已经刷新。

现有同步 `/api/check` 只可保留为合成数据演示适配器，不是受控部署业务运行入口。

### 10. 并发仲裁

每个申请处理周期维护单调 `lifecycle_revision`，每次证据变化推进 `evidence_revision`。写命令携带预期修订，并通过数据库 compare-and-set、唯一约束和短事务仲裁；不使用 last-write-wins。

命令幂等键按租户、主体、动作和目标限定，并绑定请求语义摘要。同键同内容返回原结果，同键不同内容明确冲突。

校验运行按处理周期、证据快照、治理策略发布和校验器版本建立唯一逻辑运行。一个逻辑运行可以有多个执行尝试，但只有通过生命周期修订仲裁的完整结果能成为当前依据。

工作项和 worker 使用有限期 lease、修订和 fencing token；过期 worker 的迟到提交被拒绝。消息传输只承诺至少一次，通过事务 outbox、消费 inbox、幂等处理和业务唯一约束实现一次业务效果，不宣称网络 exactly-once。

数据库长锁、进程锁、文件锁和内存全局锁不能承担跨请求或跨 worker 的受控部署并发语义。

### 11. 失败、重试与恢复

业务不一致、存疑、缺失和低置信是正常校验结果，不进入通用 `FAILED`。

只有明确可重试且幂等的瞬时技术失败可按版本化策略有限重试。策略固定最大次数、总时限、退避和抖动，并保留每次尝试。超时表示结果未知：必须先按原操作标识查询或对账，确认未执行后才可重试；无法确认时进入暂不可处理。

身份、授权、密钥、必要审计、权威存储或完整性失败时关闭失败：不提交业务事实，也不返回旧成功。worker 崩溃通过 lease 到期接管，未完成暂存结果不可见。

外部副作用在发送前建立交付义务，随后记录发送、确认、结果未知和补偿状态。部分成功通过后继补偿事实处理，不能删除或改写历史。重试耗尽、死信或补偿失败形成稳定原因、责任方、恢复目标和机器可验证的恢复条件；恢复后重新经过正常生命周期门槛。

outbox 可重放、投影可重建。策略安全冻结等失败关闭状态只能由显式恢复事实解除，不能由超时自动恢复。

### 12. 技术基线与部署拓扑

首版技术基线为：

- Python 与 FastAPI 作为控制面实现和 HTTP 适配；纯 Python 校验内核不得依赖网络或持久化；
- PostgreSQL 作为权威关系存储，并使用 SQLAlchemy/Alembic 管理持久化适配与迁移；
- 机构控制的 S3 兼容对象存储保存附件和不可变制品；
- PostgreSQL 持久任务表实现首版 job、lease、inbox 和 outbox；独立 worker 使用短事务认领；
- React + TypeScript 静态前端和 OpenAPI 生成客户端；受控运行时不需要 Node 服务；
- OCI 容器分别运行无状态 Web/API、worker、调度/对账进程和隔离评估 runner。

首版不引入 Redis/Celery、Kafka 或 RabbitMQ 作为业务或任务权威。未来若吞吐证据支持，可增加 broker 作为传输加速适配器，但 PostgreSQL 仍保存逻辑任务、幂等和业务效果。Kubernetes/OpenShift 可以作为机构部署适配器，但不成为领域语义依赖。

### 13. 公开演示与受控部署

两类环境共享纯领域模型、校验内核和契约测试，但使用不同入口、部署清单、账户、网络、存储、密钥、凭据、审计和数据管道。

公开演示只提供预置合成或经验证不可逆匿名化数据。允许的编辑保存在隔离会话中；禁止真实附件上传、全局策略发布、受控导出和处理受限数据的外部服务，会话数据最迟 24 小时清除。

受控部署采用机构单租户、OIDC+MFA 人员身份、OAuth2/mTLS 工作负载身份，以及租户、角色、资源和动作四层授权。数据库、对象存储、队列、备份及管理面无公网入口，默认拒绝公网出口，只允许登记并批准的内部或受控外部集成。

不能通过给公开演示增加共享 token 或切换一个环境变量就宣称达到受控部署基线；同时不维护两套分叉的校验业务代码。

### 14. 可观测性与审计

目标系统分离四类信号：

- 结构化运行日志记录稳定原因码、安全关联 ID 及请求/命令/job/attempt 标识；
- 指标覆盖 HTTP RED、资源 USE、队列年龄、outbox/inbox 和投影延迟、lease 过期、有限重试/死信、失效运行、暂不可处理停留、交付义务和评估状态；
- OpenTelemetry 追踪贯穿 HTTP、事务 outbox、worker 和外部集成；
- 安全审计完整、不采样、只追加并具有完整性检测。

日志、指标和追踪不得包含附件、OCR 原文、字段值、凭据、自由文本或内部路径。指标标签保持低基数，不以申请标识作为普通标签。审计不能由运行日志或 trace 替代。

公共 `/live` 只证明进程存活；详细 `/ready` 和依赖诊断只对受控运维面开放。审计断档、策略冻结/激活失败、队列或投影积压、持续 lease 失效、恢复/补偿失败、受限访问异常和交付义务超时必须告警。具体 SLA 和告警阈值由真实负载基线与机构要求确定，本决议不臆定数值。

### 15. 现有 MVP 的位置

现有源码与材料仅形成以下行为证据：

- Python 标准化、匹配、规则和报告行为可作为目标校验内核候选；
- 扁平 `Application` JSON、外部 OCR/Step2 adapter 和 fixture 是演示或迁移输入候选；
- 当前 FastAPI 和静态 UI 证明同步演示路径，不证明目标工作台、身份或生命周期；
- YAML/JSON 规则与知识、JSONL 审计和 `out/` 报告不是受控部署权威；
- 当前 fixture evaluator 是开发回归 harness，不是 ADR-0007 的正式评估运行平面。

本决议不对任何具体文件作保留、封装、重写或废弃裁决。

## Considered Options

- 继续扩展单进程同步 MVP 和本地文件：改动最少，但不能满足权威状态、跨进程并发、不可变运行、恢复或受控信任边界，拒绝。
- 一开始按每个域拆微服务和独立数据库：故障隔离较强，但会把申请接纳、运行提交、必要审计和策略影响变成分布式事务；当前没有独立伸缩或团队证据，拒绝。
- 引入专用 event store、Kafka 和多套读写存储：吞吐潜力高，但增加重放、兼容、运维和一致性复杂度，当前无证据支持，拒绝。
- 使用 Redis/Celery 或消息 broker 作为任务权威：接入方便，但会产生数据库与队列双重事实；首版使用 PostgreSQL 持久任务和 outbox，拒绝将 broker 设为权威。
- 让评估复用业务申请和生命周期路径：代码复用直接，但会污染业务状态、引入标签泄漏和扩大受限数据权限，拒绝。
- 维护两套完全独立的演示和受控业务代码：物理隔离强，但业务语义会漂移；采用共享纯核心和独立部署壳，拒绝代码分叉。

## Consequences

- 目标实现需要新增持久领域模型、事务协调、投影、worker、身份授权、对象存储和正式评估运行平面，不能把当前文件层简单包装为生产存储。
- 模块化单体保留本地事务和较低运维成本，同时要求严格执行逻辑所有权和禁止跨模块写表。
- PostgreSQL 持久任务适合当前未知但预期中等的规模；如果未来测得队列吞吐或隔离不足，需要以相同幂等、lease、outbox 和 fencing 语义替换传输适配器。
- 公开演示和受控部署必须分别验证，演示能力不能充当安全、持久化或性能证据。
- 具体云厂商、机构 IdP/KMS 产品、法定保留年限、容量/SLA 数值和现有 MVP 逐文件迁移策略仍由后续规格、机构配置和实施票据决定。
- 本 ADR 不修改生产源码、tests、fixtures、configs、GOAL.md 或 STATUS.md。
