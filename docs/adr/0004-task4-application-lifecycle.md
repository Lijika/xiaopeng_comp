# ADR-0004: 任务4以只追加生命周期事件派生申请当前态

## Status

Accepted - 2026-08-01

一致性审核工作台跨越异步接入、证据组装、版本化校验、多人复核、例外审批、取消及故障恢复；可覆写的单一状态字段会丢失因果历史，各环节分别维护状态又会产生互相矛盾的当前事实。任务4因此以**申请生命周期**作为申请状态的唯一所有者：被接受的转换形成只追加、不可改写的生命周期事件，一个互斥主阶段和受其管理的工作项共同派生可重建的当前申请态。不可变证据图、校验运行、人工处置、例外决定和安全审计保留各自事实并通过版本化引用参与转换，但都不能成为第二个申请状态所有者。

并发命令通过生命周期、工作项和证据修订仲裁，重复命令通过幂等绑定返回原结果；更正、失效、取消和重开只追加后继事件。核验完成或终止封存一个申请处理周期，后续变化创建新周期而不改写旧结论。具体数据库、事务、消息队列和投影技术由后续架构决策选择，但必须保持上述所有权、历史和失败关闭语义。

## Considered Options

- 只保存可覆写的当前状态：查询简单，但无法证明重试、并发、人工修正和重开的历史因果。
- 让接入、校验、复核和审批环节分别拥有申请状态：局部自治，但在部分失败和竞态下没有唯一当前事实。
- 以申请生命周期统一接受转换、以只追加事件派生当前态：实现与投影成本更高，但能保留不可变历史并集中执行权限、版本、幂等和恢复不变量。

## Consequences

- 当前态可以缓存和投影，但必须能从生命周期事件重建，不能反向成为权威。
- 业务状态历史与安全审计是相互关联但不同的记录；必要审计不可可靠生效时，受保护的业务转换不得被接受。
- 当前同步、无持久生命周期的 MVP 只能作为行为证据，不能直接充当目标状态模型。
