# ADR-0001: 任务4 数据范围 — 官方登记证子集 + 跨单配置预留 + 合成演示

## Status

Accepted — 2026-07-25

## Context

赛题任务4在业务叙述上要求「同一申请多份单据」交叉核验，并提及日期、金额、地址等实体标准化。  
官方配套数据实质为机动车登记证书多页影像；登记证版面提供页序/页类/检测框但无抽取文本。  
合同、保单、发票、融资金额等**不在官方公开包中**。若强行当真数做跨单指标，不诚实；若完全不做任务4能力，则与赛题能力描述脱节。

## Decision

1. **主交付 / 真数路径（官方可支撑）**  
   - 单位：**样本级机动车登记证书**（多页：注册页 / 登记页）。  
   - 能力：关键区域定位（含 4/5/6 大框、8/10 编号、VIN/发动机号等细框）→ 字段提取（有识别结果时）→ 展示 → **样本内**一致性校验（至少 8↔10 等同语义字段；可扩展跨页 VIN 等）。  
   - 数据来源：仅官方影像 + 版面（及后续识别填字），不伪造合同/金额为官方数据。

2. **跨单据能力：配置接口预留**  
   - 引擎与配置继续支持多 `doc_type`、字段别名、金额/日期/地址等规则类型。  
   - 赛题方可在不改核心代码的前提下，通过配置/界面接入其私有多单据结构化数据。

3. **演示系统：合成数据展示跨单据**  
   - Web/样例中保留「登记证 + 保单 + 合同 + 发票 + 证件」等合成 Application，用于展示跨单据三态报告与规则维护。  
   - 所有合成路径必须标记 `field_source=synthetic`（或等价），评估与报告中与官方路径分列。

4. **禁止**  
   - 将合成金额/合同等写成「官方测评结果」。  
   - 因官方无多单据而删除任务4规则框架能力。

## Consequences

- 任务4主指标与主演示叙事应优先绑定**登记证样本级**链路；跨单指标仅在合成集或赛题方自备数据上报告。  
- 实现优先级：样本级提取与展示（影像+版面[+抽取]）> 样本内校验 > 配置预留与合成跨单演示 polish。  
- 与 `docs/TASK4_DATA_REQUIREMENTS_AND_LAYOUT_ANALYSIS.md` 一致：登记证版面为任务3中间态，有框无字。
