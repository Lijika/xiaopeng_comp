# ADR-0006: 任务4以不可变原子策略发布治理规则与实体知识

## Status

Accepted - 2026-08-01

当前 MVP 允许直接改写运行时 YAML 规则和 JSON 实体知识，并让各模块读取各自的当前状态；这不能保证一次校验运行使用单一、可追溯的政策上下文，也无法满足既有不可变证据、生命周期、职责分离和失败关闭约束。任务四因此以不可变的**治理策略发布**作为唯一运行时选择单元：它按稳定标识和内容摘要原子绑定校验政策、语义字段目录、实体知识、规范化与证据就绪策略，以及兼容的校验器和输入语义契约；每次校验运行固定引用一个完整发布。

规则管理员只能维护声明式草案；权限边界、自动流转白名单、关键身份核验、证据资格和审计不变量属于独立的受保护控制基线，普通配置与紧急权限均不能削弱。草案冻结为不可变候选后，必须通过自动验证、独立审批和明确时间的原子激活；变更以保守无漏项的策略影响集驱动申请生命周期失效与重新校验。错误发布通过策略安全冻结、不可变回滚发布或向前修复处置，历史运行和治理记录不倒转、不删除。

## Considered Options

- 继续直接改写并热重载规则和知识文件：维护路径短，但会产生混合版本、不可复现运行和绕过审批的状态。
- 各工件独立发布并在运行时读取各自最新版：组件复用较灵活，但无法证明某次运行使用了唯一完整政策快照。
- 以不可变清单原子绑定所有政策组成并显式治理激活：注册、验证、影响分析和重跑成本更高，但能保持版本、权限、审计和生命周期因果一致。

## Consequences

- 策略工件注册表拥有不可变工件，策略治理账本拥有审批与激活事实，申请生命周期继续唯一拥有申请状态；三者只能通过稳定引用协作。
- 当前 Web 规则/知识写入、进程级热重载和调用方指定规则路径只能作为竞赛演示行为，不能直接成为受控部署的治理实现。
- 具体数据库、事务、消息传输、部署产品和用户界面仍由后续架构与实施决策选择，但不得破坏本 ADR 的原子版本、受保护基线和失败关闭语义。
