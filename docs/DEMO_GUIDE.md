# 任务4 放款审核使用说明

打开后按顶部编号走即可。这是同一申请下多份单据的交叉核验界面。

## 启动

```bash
bash scripts/run_web.sh
# 默认 :8765；占用时：PORT=8767 bash scripts/run_web.sh
```

浏览器打开 `http://127.0.0.1:8765/`。**务必 Ctrl+Shift+R 强刷**，避免缓存旧前端。

岗位在页面顶部切换（审核员 / 材料岗 / 特批人 / 规则管理员 / …），不必改命令行、不必改 URL。

全流程状态默认写入一次性临时目录。排查时可指定 `TASK4_FULL_DEMO_ROOT=/绝对路径`。

## 推荐 3 分钟路径

1. **第 1 步 · 单笔核验**（首页）
   - 上传 `材料/task4_applications/JFL25P02L080310-01_ok.json` → 「开始核验」→ 应看到「一致」
   - 再上传同目录 `*_vin_mismatch.json` → 再核一次 → 应看到「不一致」（合同 VIN 与登记证不同）
   - 第 2 步及之后会带上这笔申请的单据字段和核验差异，不再是空队列拼页
2. 往下滚到 **核验指标** → 点「查看覆盖率、误报与漏报」
   - 看三张主卡片：覆盖率 / 误报率 / 漏报率
   - 对照：覆盖率 ≥ 80%，误报 ≤ 5%，漏报 ≤ 3%
3. 有时间再点 **第 2 步 · 人工复核**，看不一致项如何展开给审核员

后面 8–12 步是放款后的治理闭环（投递、取消、删除、导出）。本地全流程启动后，这些页会自动带入样例。

`bash scripts/run_web.sh` 打开的页面覆盖本仓库已实现的任务4能力：首页核验与指标、人工复核、补材料、特批、规则发布与影响、成绩看板、投递、取消、终止清算、删除、导出。身份由页面岗位切换，不走终端登录。

首页核验请上传 `材料/task4_applications/*.json`。登记证 VIN 等来自抽取结果；保单/合同/发票/身份证是按同一辆车补齐的展示字段，不是主办方原文。

## 顶部导航在说什么

| 编号 | 你看到的名字 | 一句话 | 地址 |
|------|----------------|--------|------|
| 1 | 单笔核验 | 同一申请的多张单据，关键字段对得上吗 | `/` |
| 2 | 人工复核 | 系统标红或存疑后，人来判 | `/controlled/s01` |
| 3 | 补材料 | 缺页、串页、拍糊了，补一版再核 | `/controlled/s02` |
| 4 | 特批 | 业务上允许的例外，必须另找人签字 | `/controlled/s05/react` |
| 5 | 发布规则 | 业务人员改规则，不用改代码 | `/controlled/s08/react` |
| 6 | 规则影响 | 改规则前先看会拦住多少在途申请 | `/controlled/s09/react` |
| 7 | 成绩看板 | 覆盖率、误报、漏报 | `/controlled/s12` |
| 8 | 结果投递 | 把结论交给下游，本页不打款 | `/controlled/s13` |
| 9 | 取消申请 | 中途不要了，明确取消 | `/controlled/s14` |
| 10 | 终止清算 | 已终止申请的收尾 | `/controlled/s14/settlement` |
| 11 | 删除数据 | 按合规要求删副本 | `/controlled/s16` |
| 12 | 导出报告 | 独立批准后才能导出 | `/controlled/s17` |

成绩卡片上仍保留英文代码（如 `coverage`），方便对照评估报告；中文名称和一句人话写在旁边。

## 数据边界

- 登记证版面：页序 + 检测框，没有字段文本
- 登记证抽取：VIN / 发动机号 / 登记证编号 / 品牌 / 型号等（仅登记证）
- 演示 JSON：在抽取字段上补齐保单 / 合同 / 发票 / 身份证，用来验跨单据规则
- 任务4 **不做 OCR 读图**；合成集成绩不得宣传为真实 OCR 成绩
