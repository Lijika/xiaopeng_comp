# 任务4 数据需求 vs 现有资产（登记证版面 / 抽取）分析

**日期：** 2026-07-25  
**依据：** 赛题说明文档《面向汽车融资租赁的特殊介质凭证结构化提取与多附件同一性判定》  
**现有资产：** 登记证影像、版面 JSON（已放入 `data/registration_layout/`）、抽取结果（本机 `材料/registration_extract/`）  
**结论先行：** 见 §0。

## 0. 结论摘要

| 问题 | 结论 |
|------|------|
| **当前影像 + 版面是否满足任务4执行数据需求？** | **不满足作为任务4完整生产/赛题指标评估的输入。** 仅能支撑「影像与版面中间态理解」和「部分演示绑定」；**缺跨单据结构化字段值**，也缺保单/合同/发票/证件等多源单据。 |

| **版面是否满足赛题对该任务的要求？** | **部分满足任务3的中间环节，未达到任务3交付终态。** 有页序、页类型、检测框与类别；**无单元格键值、无字段文本、无整本统一 JSON**。 |

## 1. 赛题任务链条（数据视角）

```
影像（特殊介质凭证页）
    │
    ├─ 任务1：打刻/磨损底纹编码识别（VIN、登记证编号等）
    ├─ 任务2：水印干扰下内页文字提取
    └─ 任务3：页面分类排序 + 版面/表格解析 + 跨页关联
              + 多附件同一性判定（归集哪些图属于同一本/同一凭证）
              ↓
         【整本/整单结构化 JSON：字段值 + 位置溯源】
              ↓
任务4：跨单据字段对齐与鲁棒一致性校验
        （同一申请下：登记证 vs 保单 vs 合同 vs 发票 vs 证件 …）
```

赛题原文要点：

- **任务3（4）**：输出「无冗余、无遗漏的完整 JSON 文档，包含所有关键字段及页面位置溯源」。
- **任务4 前提**：「**结构化提取后**」对同一申请多份单据交叉核验。
- **任务4 能力**：字段标准化与实体链接；配置化多层级规则；三态结论 + 快照/差异高亮。
- **任务4 指标**：覆盖率≥80%，误报≤5%，漏报≤3%（相对带标签的交叉核验集）。

因此任务4的**最小可执行数据**不是影像本身，而是：

### 1.1 任务4 输入数据需求（规范）

| 层级 | 必需内容 | 说明 |
|------|----------|------|
| **申请（Application）** | `application_id` | 一笔放款/进件 |
| **多单据（Documents）** | ≥2 种业务单据类型 | 典型：机动车登记证书、交强险/商业险保单、融资租赁合同、发票、身份证/营业执照等 |
| **字段（Fields）** | **字段名 + 文本值（raw）** | 如 VIN、发动机号、姓名、证件号、车牌、金额、日期、地址、登记证编号… |
| **可选质量信号** | confidence、source_page、bbox | 支撑「存疑」、溯源 |
| **跨单对齐键** | 同义字段/别名 | owner_name ↔ lessee_name ↔ insured_name 等 |
| **评估标签（若报指标）** | 每规则 expected 一致/不一致/存疑 | 否则只能做演示/冒烟，不能诚实报 FPR/FNR |

**任务4 不要求在模块内完成 OCR**，但**要求上游给出字段值**；仅有框无字时，无法做真实一致性比对。

## 2. 现有资产盘点

### 2.1 登记证影像（赛题方子集）

| 项 | 实测 |
|----|------|
| 规模 | **21** 个申请/凭证目录（`JFL…-01`） |
| 文件 | **97** 个影像（png 72 + jpg 25） |
| 内容 | 以**机动车登记证书**类影像为主（多页拍摄） |
| 标注 | **无**结构化字段 JSON、无跨单据类型 |
| 与全库 | 赛题描述约 700 本 / 3000 页量级；本 zip 仅为**很小子集** |

**对任务4：**

- ✅ 可理解「单本登记证多页影像」形态、命名与申请 ID 粒度  
- ❌ **无字段文本** → 不能直接喂任务4引擎做真实交叉核验  
- ❌ **几乎只有登记证影像**，缺保单/合同/发票/证件等同申请多源单据  
- ❌ 不足以构造赛题口径的「跨单据」评估集（除非人工标或另源合成）

### 2.2 `data/registration_layout/*_page_order.json`

| 项 | 实测 |
|----|------|
| 规模 | **10** 本（均落在 登记证影像 的 21 本之内；登记证影像 另有 11 本无 版面） |
| 顶层字段 | `sample_id`, `generated_time`, `pages`, `statistics`, `warnings` |
| 每页 | `order`, `filename`, `page_numbers`, `inferred`, `page_type`, 标记位, `detections[]` |
| 检测框 | `bbox`, `confidence`, `class_id`, `class_name_cn` |
| **文本值** | **无**（detections 无 text/value/ocr 字段） |
| 页类型分布 | 注册页 11 + 登记页 33（版面 内） |
| 检出类别示例 | 车辆识别代号/车架号、发动机号、登记证书编号、车辆品牌/型号/类型、制造厂、登记栏、页码、凸字… |

**生成时间戳字段** `generated_time` 表明为流水线中间产物（本仓库侧 版面），不是赛题官方最终标注包。

## 3. 版面 归属：对应哪一任务？

### 3.1 与任务3的对应关系（强）

| 任务3 子项 | 版面 是否覆盖 |
|------------|----------------|
| （1）页面类型自动分类 | ✅ 有 `page_type`（注册页/登记页） |
| （1）逻辑排序 | ✅ 有 `order` / `page_numbers` / `inferred` |
| （2）嵌套表格结构解析 | ⚠️ 仅有区域框与类别名，**无行列/单元格/键值树** |
| （3）跨页字段一致性约束 | ❌ 无字段值，无法做值级约束 |
| （4）整本统一结构化 JSON（关键字段+溯源） | ❌ **无字段值**；仅有位置级中间态 |
| 多附件同一性判定 | ⚠️ 本数据按**已分好的 sample 目录**组织，未见「乱序多图归集」任务输出形态 |

→ **版面 = 任务3 前半段（分类 + 排序 + 字段区域检测）的工程中间产出**，不是任务3 终态交付物。

### 3.2 与任务1/2 的关系（弱/间接）

| 任务 | 要求 | 版面 |
|------|------|-------|
| 任务1 | 打刻/磨损底纹下编码**字符识别** | 有「凸字」「登记证书编号」等**框**，**无识别字符串** |
| 任务2 | 水印下内页**文字提取** | 无 |

→ 版面 **不能**替代任务1/2 产出。

### 3.3 与任务4 的关系

| 任务4 需要 | 版面 |
|------------|-------|
| 多源单据字段值 | ❌ 仅登记证页、且无值 |
| 标准化/比对 | ❌ 无 raw 文本 |
| 评估标签 | ❌ 无 |

→ 版面 **不能单独驱动任务4**；最多提供：

- `sample_id` / 页序 / 框类别，用于**溯源展示**或**引导 OCR 裁剪**；
- 与合成/外部 OCR 字段拼接成 Application JSON（本仓库 fixtures 的 `meta.layout_sample_id` 即此用法）。

## 4. 版面 是否满足赛题对「该任务」的要求？

此处「该任务」= **任务3（版面解析与跨页关联 / 含多附件归集）**。

### 4.1 已对齐的部分

- 页面类型标签空间（至少注册/登记）  
- 阅读顺序 `order`  
- 字段区域检测（VIN、发动机号、登记证编号等类别）  
- 与影像文件名关联（`filename`）  
- 统计与 warnings 结构，便于工程串联  

### 4.2 未满足 / 明显缺口

| 赛题要求（任务3） | 缺口 |
|------------------|------|
| 页面分类准确率 ≥98% | 无 GT 标签集与评测报告 |
| 整本结构解析准确率 ≥95% | 无层级表格/键值 JSON |
| 跨页字段关联准确率 ≥95% | 无字段值，无法关联比对 |
| 完整 JSON（关键字段+位置溯源） | 仅有框，无值 |
| 多附件同一性判定模块 | 未体现乱序归集输入输出 |
| 覆盖规模 | 10 本 vs 影像 21 本 vs 赛题约 700 本 |

**判定：** 版面 是**有价值的任务3中间结果**，**尚未达到赛题任务3交付与指标口径**；也**不能**被表述为「任务3已完成」或「可直接进入任务4真数评估」。

## 5. 对任务4 的可执行性矩阵

| 任务4 工作项 | 仅 登记证影像 | 登记证影像+版面 | +合成/标注多单据字段 | +真 OCR 多单据 |
|--------------|----------|-------------|----------------------|----------------|
| 引擎开发/单测 | ❌ | ⚠️ 间接 | ✅ | ✅ |
| Web 演示（说明链路） | ⚠️ | ✅ 可展示框/页序 | ✅ | ✅ |
| 合成集指标（自建标签） | ❌ | ❌ 需另造字段 | ✅（本仓库现状） | ✅ 更佳 |
| 赛题口径跨单据指标 | ❌ | ❌ | ⚠️ 需声明边界 | ✅ 接近 |
| 与任务1–3 端到端 | ❌ | ❌ | ❌ | ✅ |

**本仓库现状：** 任务4 模块 + **合成多单据 fixtures**（部分 `meta.layout_sample_id` 绑定）→ 可开发、可演示、可自建评估；**不能**声称基于 登记证影像 真 OCR 的跨单据指标已达标。

## 7. 建议路径（在现有资产上继续）

1. **短期（演示/开发）**  
   - 保持合成多单据 + `layout_sample_id` 绑定（已做）  
   - UI 明确区分「检测框」与「字段值」来源（已做引导）  

2. **中期（半真实）**  
   - 按版面框裁剪登记证影像 → 外部 OCR → `import_external_ocr` → `fixtures/semi`  
   - 评估 **suite=semi** 与 **main** 分家（架构已定）  

3. **完整赛题闭环**  
   - 补齐任务1–3：字段值 JSON + 多附件归集  
   - 引入同申请多源单据（保单/合同/发票/证件）真数据或官方集  
   - 再报任务4 三项指标

## 8. 一句话备忘

- **登记证影像**：任务1–3 的**影像输入子集**，不是任务4输入。  
- **登记证版面**：任务3 的**页序/页类/区域检测中间产出**，有框无字，**未达任务3终态，也不满足任务4单独执行**。  
- **任务4 真跑跨单据一致性**：必须有**多单据字段值**；当前仓库用合成 JSON 填补该缺口，并诚实声明边界。
