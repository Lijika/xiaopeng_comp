这个演示在做什么？

放款审核时，同一笔申请会有多份材料：机动车登记证书、交强险保单、融资租赁合同、发票、身份证 等。 任务4不负责「从照片里认字」（那是任务1–3），而是在已经提取出的结构化字段上，做跨单据对齐与一致性校验。

（1）

字段标准化与实体链接

日期/金额/地址/VIN/车牌/姓名等写成统一形式；模糊匹配 + 知识库消解「苏A·12345」与「苏A12345」等变体。

（2）

多层级规则框架

完全一致、数值容差、列表包含、条件必填等，配置化；业务可在「规则维护」页改规则并生效。

（3）

三态可解释报告

每个校验点输出一致 / 不一致 / 存疑，并给出各单据字段快照与差异高亮，方便人工复核。

数据说明：1.zip 为赛题方提供的登记证影像样例； step2-排序 为我们做的页序/区域检测结果（有框无 OCR 文本）。 本演示用的「多单据字段」是按业务构造的结构化申请 JSON（模拟任务1–3 输出），用于单独验证任务4能力。

赛题数据从哪来？（1.zip → step2 → 任务4）

  1. 1.zip：赛题方登记证影像（本仓库仅部分样例）
  2. step2-排序：页序 + 字段区域检测框（有位置、无 OCR 字）
  3. 任务1–3（赛题其它模块）：识别文字 → 结构化字段
  4. 任务4（本页）：多单据结构化字段交叉校验
选择 step2 样例可看到登记证上检出的字段区域；下方演示仍用多单据 JSON 做交叉校验。
